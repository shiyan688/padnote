# Android PDF 导出验收

2026-09-23；对应 Android beta.6 / code 45。

本次目标：标准 PDF 包含纸面上的正文、公式、图表、笔迹、插图及原 PDF 背景；不能只包含 OCR 页面图。

## 实现

- 从当前笔记冻结页几何、笔迹、图片位置和文字片段，并独立打开 PDF 背景。
- 后台逐页绘制基础图层；文字使用附着的离屏 WebView，等待离线字体、数学、图表及视觉状态回调。
- 导出保持各片段的页码与位置。未实测过的片段若实际内容高于预留区域，会整体缩小以保留内容；超过两页高的单片段渲染范围则报错。CSS 高度先换算为设备像素，输出缩放作用于整个片段。
- 整份 PDF 先写缓存临时文件，完成后再写用户选择的目标，目标流关闭后才报告成功。主线程文字渲染按页最多等待 30 秒，失败、超时和内存不足有错误提示。
- 页面关闭、任务拒绝和渲染结束均清理导出视图及独立 PDF 资源。

## 回归重点

- 纯文字笔记：标题、中文、列表与正文出现在 PDF 中。
- 混合笔记：LaTeX 公式和 Mermaid 图表完成渲染，手写笔迹、插图的位置保持正确。
- 多页笔记：停在第一页直接导出，后续页的文字仍完整；跨页文字使用各自片段，不把整段内容重复画到每页。
- PDF 批注笔记：原 PDF 每页底图仍在，新增内容在正确页、正确位置。
- 视口独立：缩放、滚动、当前选区或编辑控件不进入导出文件。
- 失败处理：渲染失败、超时或写出失败不能显示“已导出标准 PDF”。生成阶段失败不应先截断用户选择的目标文件。
- OCR 保持原行为：整页数字化的页面图片仍刻意排除文字流，文字源另行提供，避免重复识别。

## 实际平板检查

1. 安装本轮 beta.6，导入 [排版体验笔记](fixtures/paper-layout-demo.padnote.json)。
2. 在笔记中增加一段手写、一张图片，并让较长正文延续到下一页；再添加一个独立 LaTeX 文字对象。
3. 停在第一页，调整缩放后选择“导出 → 标准 PDF（页面已合并）”。完成后用独立 PDF 阅读器打开。
4. 逐页对照原笔记：标题、步骤编号、公式右端、图中文字和箭头、跨页正文、笔迹及插图都应存在；没有选框、操作手柄或工具栏。
5. 另导入一份至少两页的 PDF，在不同页添加文字与手写，然后重复导出，检查底图和新增内容。
6. 若公式或图表源码本身有误，检查导出与纸面上的错误提示一致。遇到资源加载失败、渲染超时或写出失败时，应明确提示失败，不能把缺内容的文件当作完成。

## 实现复核依据

- [Android WebView](https://developer.android.com/reference/android/webkit/WebView#postVisualStateCallback(long,%20android.webkit.WebView.VisualStateCallback))：DOM 更新不等于下一帧已可绘制；导出视图需满足附着与可见性条件，等待视觉状态回调。
- [Android PdfDocument](https://developer.android.com/reference/android/graphics/pdf/PdfDocument)：文档不是线程安全对象，逐页串行处理，已开始的页需要完成后再关闭文档。
