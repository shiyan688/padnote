# 开发状态与接手入口

## beta.32 WSL 任务文件核对

Windows 连接助手会在把任务交给 WSL Hermes 前核对所选发行版、配置身份和当前任务输入文件摘要；任务文件检查失败时，不会发送 Hermes 请求。后续任务引用原任务输入，并使用自己的输出目录。发行版需要处于运行状态；任务投影不会为了提交任务而启动它。

父任务材料是经过摘要核对的工作流参考，不是操作系统级只读沙箱。WSL 中同一用户仍可能访问相应的 Windows 文件。提交状态不确定时，应查看原任务结果，不要自动重发。

桌面自动回归为 459 项（453 通过、6 跳过、0 失败）。另有 22 项 WSL 任务上下文聚焦回归（helper/Hermes 13 项、Bridge 9 项），以及 6 项 Windows 本地任务路径 probe（5 通过、1 项 POSIX 专属用例跳过、0 失败）；probe 使用 FakeManager、合成文件和阻塞输入的子进程，没有访问真实 WSL、注册表、Hermes 配置或模型。真实 Windows/WSL/Hermes 请求仍须单独验收；这些自动化检查不代表真实发行版或 Agent 已连接。Windows 助手版本为 beta.32；Android 继续使用已发布的 beta.29、versionCode 65，本轮未更改 Android。操作步骤见 [beta.32 检查指南](../BETA32_TESTING.md)。

目标：在平板与 AI 在同一张纸上交流学习，方便分享给人，也能把上下文交给自己选择的电脑 Agent。模型、语音和工具由用户或 Agent 选择；当前不建设 PadNote 自有服务器。

## beta.31 WSL 操作恢复

Windows 助手的 WSL 向导在操作结果未知时允许返回选择，并保留原操作供之后主动查看状态。用户点击“取消等待”后立即离开当前等待；请求确认期间后台操作仍可能继续，PadNote 不会据此停止 Hermes、重发连接或把未知结果改判为失败。迟到的扫描、配置查找和状态响应不能覆盖新选择或配对目标。原生启动器新增“在 WSL 中查找”直达入口。

53 项相关 Python 回归通过（原生启动器 34 项、管理页 19 项）；两份 Playwright DOM 检查通过，使用合成数据和本地模拟 HTTP。Windows 旧版覆盖升级已在一台电脑验证，243 项安装文件匹配构建清单，Setup 前后用户状态文件一致，启动后的任务和配对归属保持。真实 WSL/Hermes 连接与模型请求仍需按所选配置验收。Windows 连接助手为 beta.31；Android 沿用 beta.29、versionCode 65，本轮没有 Android beta.31。[操作检查](../BETA31_TESTING.md)。

## beta.30 WSL 配置与多 Agent 连接

Windows 助手管理页新增 WSL 连接向导：用户扫描发行版、明确选择发行版和 Hermes 配置，先查看不含密钥值的变更预览，再明确启用本机连接或启动并连接。连接成功后，用户选择刚连接的 Agent 完成配对。多个配置分别对应各自的 Agent 身份、凭据和任务归属。

助手使用用户自己的 Hermes 配置，密钥只在进程内存中使用；重新打开助手后须明确重连。取消只取消 PadNote 的等待，不会停止 Hermes。未知网关模式先使用默认配置，再由用户选择命名配置；不会自动更改 provider 或重启外部管理的网关。

桌面回归为 438 项、432 项通过、6 项跳过、0 项失败，其中包括 16 项 WSL 核心、配置、HTTP 与身份检查；新旧管理页面 DOM 检查另行通过。Windows 原生被动枚举通过，未改变发行版运行状态；Linux 四项隔离进程检查通过，覆盖并发启动与不确定结果下的重放防护。Windows beta.30 Setup 与 Portable 的包内容、源码对应关系和 PE 版本独立核验通过。安装流程及真实 Hermes 连接、配对尚待验收。Android 沿用 beta.29、versionCode 65；本轮没有 Android beta.30，也没有新增七语言资源。[beta.30 操作检查](../BETA30_TESTING.md)。

## beta.29 视角恢复与连接引导

Android 将每份笔记的浏览位置单独保存。只做缩放、平移或调整窗口尺寸时，不创建新的正文版本；返回书架或切到后台后，重新打开可恢复最近的视角。旧笔记没有本机位置记录时，仍使用笔记中原有的视角。位置保存与正文保存分别处理，不能阻挡分享、视频或交给 Agent 的后续操作。

电脑助手将“未在常见位置找到 Hermes”与“尚未安装”区分开。多个配置时，提示直接通向已有配置列表；使用自定义安装目录的用户，可以进入本机 API 表单。WSL 发现向导在 beta.30 中加入，见上节。

## beta.27 笔记移除与完整恢复

书架增加“已移除笔记”入口。对采用完整版本存储、保留移除历史的笔记，先重新校验移除版本及其直接前一版本，再展示材料摘要，由用户确认恢复原笔记。恢复包含已保存的文字、笔迹、PDF、封面、视频和 Vault/知识库成员；同一 local ID 与 lineage 发布新 revision，旧任务不会自动转向新版本。编辑草稿与 AI 会话不是 group 成员，不列入完整版本恢复保证。

恢复前绑定当前版本与用户预览的来源版本，提交时再次比较完整成员集合、大小与 SHA-256。取消在提交审批边界前生效；跨过该边界后，已授权的恢复可以完成。遇到可能发生在发布后的错误，界面会要求重新检查结果，不保证“原内容未改”，也不自动重放操作。

旧格式删除改为独立的持久提交记录。临时文件和旧索引不能充当删除已提交的证明；只有经过校验与目录同步的 canonical 记录才授权清理。旧索引或恢复文件不能使已提交删除的 ID 重新出现。无法精确核验的 PDF、封面、视频、会话和草稿等残留材料会保留并提示清理待完成，本批不做宽泛回收。旧格式笔记的永久删除不在已移除列表的恢复范围内。见[用户指南](BETA27_TESTING.md)。

Android beta.27 versionCode 63 的最终 R7 构建：54 suites / 412 JVM tests，0 failures、0 errors、0 skipped；lint 0 errors、162 warnings；4 ABI、原测试签名。Instrumentation tests 仅编译，未在设备运行。此前编译与测试中的失败记录保留，分发物使用最终 R7。新增的一条 lint warning 是旧清理提示字符串不再使用。Windows 连接助手继续 beta.20，iPad 本轮未改代码。现有演示素材重新安排到 GitHub 首页首屏，没有新增本版本实机录像。

后续仍需完成旧格式残留材料的安全回收与可见重试、书架索引全部丢失时的移除历史发现、损坏删除记录的逐笔记隔离，以及长材料检查与取消的设备性能测量。Legacy mutation gate 是进程内锁，本批不声明跨进程协调保证。两端界面整理在独立候选中推进，不计入本轮构建。

## beta.26 草稿检查与恢复

无法读取的编辑草稿先在后台检查，取得完整的当前文件校验后才显示丢弃确认。清理前再次核对同一笔记、存储目录及完整文件集合；后来保存或替换的文件不会被旧确认删除。草稿正文的 8 MiB 解码上限保持不变，超限恢复文件采用固定缓冲的流式校验。有效草稿从备份或临时恢复文件读回后的清理也已覆盖。

恢复读取开始前会暂时保护文字编辑入口，确认没有草稿后解除；检查状态由当前请求管理，结束时不会留下“正在检查”或覆盖较新的纸面状态。检查和清理使用独立后台队列，并区分完成、取消、文件变化、大小限制、超时和清理失败。原笔记正文不被草稿清理改写。中英文操作说明见 [草稿恢复指南](BETA26_TESTING.md)。

安全检查以单次完整文件集合合计 128 MiB 为上限，双遍复核最多读取 256 MiB，并共享 5 秒检查预算；普通有界解码另受原来的 8 MiB 上限保护。超过预算时保留记录，不声称可清理任意大小的损坏文件。同步的普通草稿读写路径与进程内存储锁仍需持续测量。

Android beta.26 versionCode 62 的最终构建：53 suites / 403 JVM tests，0 failures、0 errors、0 skipped；lint 0 errors、161 warnings；4 ABI、原测试签名。Instrumentation tests 仅编译，未在设备运行。Windows 连接助手继续为 beta.20，iPad 本轮未改代码。

## beta.25 PDF 页面尺寸

PDF 页面物理尺寸现在独立于图像栅格分辨率。A4 比例笔记使用 A4 页面；屏幕比例和旧格式保留原比例并放入 A4 外框，因此页面本身不一定是标准 A4；带 PDF 背景的笔记统一采用源文件第一页的显示尺寸，混合尺寸背景按比例放入页面。导出的 PDF 是纸面图像，不包含可搜索或复制的文字层。若纸张尺寸超出支持范围，应用会在打开系统保存器前提示；原笔记保持不变，可调整尺寸后重试。OCR 使用的栅格流程不受 PDF 物理尺寸限制。

导出不会改写笔记页面几何、手写、文字分页、页数、撤销状态或源 PDF。相同内容的草稿保存会去重；草稿不是逐键自动保存。详见 [beta.25 PDF 页面尺寸检查](BETA25_TESTING.md)。

Android beta.25 versionCode 61 的候选构建：53 suites / 390 JVM tests 全通过；lint 0 errors、161 warnings；4 ABI。Instrumentation tests 仅编译，未在设备运行。

## beta.24 手动文字编辑

手动编辑失败时，原文字和纸面布局保持不变，编辑内容留在编辑器中，可修正后重试或明确取消；新文字通过排版检查后才提交，成功后可用一次“撤销”还原。重开笔记时，用户可以选择继续编辑已保存草稿、稍后处理或丢弃；匹配按笔记中的文字流与基线原文进行，不依赖瞬时 fragment ID，也不会自动覆盖笔记。草稿保存有容量上限，不是逐键保存。

Android beta.24 versionCode 60 的构建和产物核验通过：52 suites / 381 JVM tests，0 failures、0 errors、0 skipped；lint 0 errors、161 warnings；4 ABI，app 与 instrumentation APK 使用原测试签名。Instrumentation tests 仅编译，未在设备运行。相较 beta.23 增加的 2 条 lint warning 均为不再使用的旧提示字符串（`UnusedResources`），无功能影响。

每条草稿最多 1,000,000 UTF-16 units、4 MiB UTF-8、8 MiB JSON record。超过上限时应提示无法保存并保留编辑器内容。beta.24 当时无法在应用内按 hash 丢弃超过 8 MiB 的损坏草稿；beta.26 已增加受限的完整文件检查与明确丢弃流程，超出其大小或时间预算时仍保留文件。具体检查步骤见 [beta.24 手动文字编辑检查](BETA24_TESTING.md)。Windows 连接助手仍为 beta.20。
