# 按笔记保存 AI 会话

对应 TODO 问题9。本文是后续实现契约，不能视为已经完成；最终状态见 `TODO_EXECUTION.md`。

## 用户操作

每本笔记先提供一个可恢复会话。关闭浮窗表示收起；清空历史使用独立操作。收起或离开笔记时，本地取消在途请求并失效晚回，不声称供应商已停止处理或退回费用。

工具栏在没有新圈选时也可恢复该笔记会话。有新圈选时明确区分“继续旧材料”和“用当前圈选更新材料”；用户选择更新前，预览、发送材料和来源绑定都沿用同一旧快照。

重新打开显示之前的聊天及每轮实际执行者。普通回答显示使用的模型；两段式分别显示转写和回答模型；电脑任务显示具体连接及 Agent。配置了电脑 Agent 不代表普通 AI 回答自动走电脑。

## 可见记录与发送上下文

可见聊天记录与实际发送历史分别存储。材料、读取范围、写权限、工具版本、接收者或原文发生边界变化时，可以保留旧记录供查看，但旧正文、图片、转写和工具结果不能自动带进新请求。

发送前、模型返回后、写入前检查同一会话ID、代次、笔记、接收者、材料与权限绑定。取消、清空、切笔记或重建上下文都使旧回调失效。权限和接收者的变更不能仅更新界面标签。

Android 的模型选择、保存、删除必须在写入配置 Store 前检查请求/材料读取状态；已打开的对话框在真正提交时再检查一次。不能先改配置，再因忙碌跳过清理。发送前还要复核当前配置与历史绑定，作为第二道检查。

更换密钥即使模型名和地址不变，也属于接收者配置的一次修订。使用本地配置修订号或凭据代次，不把密钥、密钥摘要或 Authorization 写入会话文件。

## 连续工具修改的来源

iPad 当前不可变 `toolNote` 不能一直充当后续写入的来源。只有本轮来源和权限检查通过、实际提交成功且当前文档与提交结果一致，才能把会话工具基线推进到这次已提交的文档；历史消息与基线一起保存。

纯回复、读取、拒绝和无变化操作不会推进文档基线。用户后来手写、移动页面、编辑文字或撤销结果，都不能冒充会话自己的提交。最小方案是在内容不兼容时停止沿用旧上下文，明确让用户以当前笔记开始新上下文；不能只更改时间戳来绕过来源保护。

复用 `NoteAIMutation.sourceCompatible` 的内容比较；滚动、缩放及保存时间不使来源失效。Android 继续保留请求的笔记ID与修订校验。

PDF笔记的来源还包含附属PDF的摘要。只比较页数和笔记JSON不足以检测原文替换；PDF缺失或变化时隔离旧发送上下文。摘要在创建/加载等边界受控计算，不能每次书写或逐轮在主线程重读大型PDF。

## 本地存储

每会话独立、有版本号的原子文件；有界读取、编码字节预算和损坏隔离。保存有界聊天、材料摘要/冻结副本、来源绑定、执行者的安全展示字段、配置修订及会话代次。端点展示不包含 userinfo、query 或 fragment；不存模型密钥、Agent令牌。

选择图片与材料沿用现有大小限制。聊天和工具结果需要额外的会话总预算；超限明确要求新上下文，不能静默截断后继续声称记忆完整。结果卡持久化需要稳定对象ID与可验证的修改凭据，不能把运行时序号或“曾经插入”布尔值当作恢复授权。

首轮预算：整会话按实际JSON编码最多8 MiB，单份选区PNG最多4 MiB，可见消息与发送消息合计最多2 MiB/200条；知识库仍为单份512 KiB、合计2 MiB、最多12份。base64和JSON转义计入总量，不因各组件单独合格就跳过总量检查。PNG恢复前检查图片头和像素规模：任一边不超过2048像素，总像素不超过4,000,000；不能仅限制压缩字节数。尽量在发送前检查容量，保存失败时保留内存结果与旧有效文件并提供导出。

保存失败应保留当前可见结果并显示未保存。超出可续聊格式上限的结果仍需提供有界的只读文字导出，不把它标成可恢复会话，也不静默截断。损坏会话保留为恢复项，不直接覆盖唯一副本。清空先失效在途回调，再删除会话及无引用图片，防止晚回重新写回已删除内容；自动生成的未保存副本也受同一清空代次约束。

清空使用持久化的无敏感代次标记阻止旧进程对象或旧写操作复活会话。删除笔记时也删除关联会话。会话默认仅保存在本机，不随单本笔记交换文件导出；后续整库备份需单独定义范围。

本机存储与系统云备份是不同边界。Android已有整应用备份排除；iPad会话目录也需明确设置备份排除属性，不能因为放在Application Support就声称不会被备份。属性检查只能证明应用设置，实际系统备份/恢复仍需设备验证。[Apple备份说明](https://developer.apple.com/documentation/foundation/optimizing-your-app-s-data-for-icloud-backup)

磁盘写入与大型摘要计算不得放进逐点书写路径。会话存储使用有序快照/代次检查，使后台写入、收起、清空与晚回之间保持一致。

## 模型能力

以当前配置身份维护未知、工具已验证、明确拒绝工具参数等状态。合法工具调用才构成支持证据；一次纯文字回答不能证明不支持工具。端点、模型、模式或凭据代次改变后重置。不得为探测能力自动发起付费调用。

## 验证

- 不同笔记隔离；收起重开、进程重建保留，明确清空删除。
- 修改材料/权限/接收者后，实际请求字节不含旧敏感标记；晚回不会恢复旧上下文。
- 忙碌时选择、保存或删除配置不改变 Store；结束后合法切换清理旧发送历史。
- 同一会话连续两轮真正提交成功；用户插入新笔迹后，旧来源不会继续写入。
- 损坏、超限、写入失败和清空竞态保留可恢复数据，不记录凭据。
- 能力状态与每轮执行者有实际请求证据；模拟器、注入网络与真机验证分别记录。
