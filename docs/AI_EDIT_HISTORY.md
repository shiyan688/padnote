# AI 修改的撤销与结果状态

本文件约定 TODO 问题8的行为。实现及验证状态以 `TODO_EXECUTION.md` 为准；公开 beta.6 不具备这里描述的完整流程。

## 一次请求对应一组修改

一次用户发送可能触发多轮笔记工具。记录应归属这次发送，而不是每次工具调用。纯读取、拒绝执行和没有实际变化的操作不增加撤销记录。取消后已经落笔的部分也应保留来源及撤销入口。

工具调用 ID 的去重范围也是一次用户发送。同一请求重放同一工具和参数时应返回已保存的工具结果，不再执行；相同 ID 携带不同参数则明确拒绝，不能省略模型协议要求的工具结果消息。

连续的同一请求修改可以在普通撤销中合并；请求之间或夹入的用户操作保留各自历史。不能为等待网络而持续开启画布编辑事务，避免把用户手写收进 AI 修改组。

“撤销本次 AI 修改”按对象差异恢复，不用请求开始时的整本笔记覆盖当前内容。用户期间或之后写的笔迹、插入的图片及其他文字必须保留。AI 创建对象、修改已有对象以及创建后再调整同一对象，都使用稳定对象 ID 关联请求前和最终状态。

## 先判断实际内容，再显示操作

结果卡查询当前文档，而不是依靠“曾经插入过”的布尔值：

- 结果仍在且与此次修改一致：可定位、撤销。
- 结果已撤销且恢复位置未冲突：可重新应用；不再次调用模型，不生成重复对象。
- 用户改过目标文字、样式或位置，或者同一 ID 已被不同对象占用：明确显示冲突，操作前检查，不能静默覆盖用户修改。
- 普通撤销/重做使结果只剩一部分：明确显示状态，不能冒充完整应用或完整撤销。

文档内容和作者设置决定冲突。滚动、缩放、保存时间及渲染器派生测高不属于用户修改目标对象。不同笔记之间不共享结果操作授权。

如果 AI 新增了尾页，撤销时只回收可以确定仍未被用户使用的空页。承载后续笔迹、图片或其他文字的页面保留。原文改变后拒绝旧请求写入的既有保护仍保留；选择性撤销不允许绕过来源检查。

用户手动增删或重排页面后，旧记录不能把新增空页当作 AI 的页面收回，也不能向失效的原页号重新写入。渲染器晚到的测高可以更新结果的占用范围，但不能扩大 AI 对用户页面的所有权。

仍在书写、擦除或拖动时，AI 写入、撤销和重新应用都应先拒绝执行。不能把活跃笔画的中间状态保存成另一项修改的撤销快照；用户抬笔后保留完整笔迹，回答文字仍可留在卡片中。

## 验收要求

1. 同一请求分多轮创建两个文字流并调整样式，一次撤销覆盖整组；重新应用恢复相同对象 ID。
2. 纯读、工具报错或无变化设置不占用撤销步。
3. AI 已写入部分结果后，用户手写，再取消请求；撤销 AI 后手写完整保留。
4. 用户改过 AI 文字，撤销/重应用前发现冲突并保持当前内容。
5. 卡片操作、工具栏撤销/重做交替后，状态与实际对象一致，不残留错误的“已插入”状态。
6. AI 只扩展的空页可回收；用户后来在该页写字、放图或新增页时，页面与内容保留。
7. 长公式和跨页文字在恢复后重新排版，原始源码不改变。
8. 切换笔记、关闭面板、过期请求回调不能向另一份文档应用记录。
9. 不同用户请求即使收到相同工具调用 ID 也各自执行；去重只作用于同一次请求。请求 A 创建的对象被请求 B 修改后，先撤销 B 才能安全撤销 A。
10. AI 修改已有对象后，该对象被用户删除时不能悄悄重建；AI 新建对象被删除后，只在用户显式重新应用且位置仍安全时恢复。
11. 用户未抬笔时，工具修改和结果卡操作都不改变文档或增加撤销记录；继续书写并抬笔后，普通撤销不会把笔画截成中途的快照。

自动化测试应区分纯差异算法、实际画布/历史操作和真实界面点击。没有真机时，触笔手感、锁屏与系统回收仍需后续验收。
