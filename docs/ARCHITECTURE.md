# PadNote 鸿蒙端架构

## 产品主链路

```text
手写笔事件
  → 原始点流（坐标 / 时间 / 压力）
  → 笔画文档
  → 本地持久化
  → 套索命中一组笔画
  → 区域渲染图 + 笔迹 JSON + 用户意图
  → AI 网关
  → 讲解 / Markdown / 正式文稿
  → 结果卡片回写笔记
```

原始笔画必须是事实源，不能只保存截图。截图方便视觉模型理解，点流则负责无损缩放、撤销、套索命中、重排和未来的笔迹搜索。

## 代码分层

- `pages/Index.ets`：ArkUI 原生输入与当前单页工作区。
- `model/InkModel.ets`：跨平台也能复用的 JSON 数据结构。
- Android `NoteCanvasView`：MatePad Air 兼容路线的墨迹、局部橡皮、套索和选区渲染。
- Android `NoteStore`：`notes/<id>.json`、轻量索引、旧文件迁移和无损交换格式。
- Android `MainActivity`：书架、编辑器、Storage Access Framework 和浮动 AI 对话卡。
- Android `OpenAiCompatibleClient` / `AiConfigStore`：多模态 provider 适配与 Keystore 加密 BYOK。
- Android `AiMathWebView`：以自托管 KaTeX 离线显示 AI 回复中的 LaTeX，不允许 WebView 网络加载。
- Android `TextFlow`：页面文字的唯一事实源与唯一写入点。持有源码、格式、字号、行宽和页相对锚点 `(pageIndex, xInPage, yInPage)`。
- Android `NoteTextBox` / `NoteTextBoxView` / `CompiledTextWebView`：由流派生的单页片段、可缩放覆盖层，以及禁网的 LaTeX/Markdown 编译显示。片段不持有独立内容，也不参与持久化。

## 页面文字的分层

```text
手势（拖拽/缩放/双击）        将来：模型 tool_call
              ↘              ↙
        操作层（改 flow，绝不改片段几何）
                    ↓
        TextFlow（唯一事实源：源码 + 页相对锚点）
                    ↓
        layoutFlow（纯函数，无副作用）
                    ↓
        HeightMeasurer（现为校准估算，可换 WebView 实测）
                    ↓
        片段视图池（按可见页虚拟化）
```

四条约束支撑"人和大模型是同两类用户"这个目标：

1. **锚点用页相对坐标**，不用世界坐标 Y。"移到下一页"对人是拖拽、对模型是 `anchorPageIndex += 1`，是同一个操作，且不可能落在两页之间。
2. **任何变更都走"改 flow → 重新派生片段"**。片段几何没有独立事实性，所以不存在片段与流不一致的状态。
3. **`layoutFlow` 是纯函数**，因此变更预览＝用候选值跑一遍布局。人的拖拽幽灵预览和将来模型的变更预览复用同一条路径。
4. **模型只能建议排版，不能写几何**。模型看不见渲染结果也量不了高度，写 rect 一定错；语义建议（该在哪断、字号多大）由模型给，最终几何永远由 `layoutFlow` 算。

任何只能通过手势触发的能力，等于对模型不存在——这是新增功能的验收线。

## 关键工程决策

1. 鸿蒙端先用 ArkUI 原生 Canvas，不引入 GPL/AGPL 手写框架，商业授权边界最干净。
2. AI 调用经过本地统一接口，模型供应商不进入页面代码。
3. 第一版 BYOK（用户填自己的 Key）；正式上架不能把 Key 明文写进笔记 JSON。
4. 默认只上传圈选区域，不上传整本笔记；调用前展示将要发送的数据。
5. 后续 iOS/Android 可共享文档格式、AI 网关协议和大部分业务状态，但高性能墨迹层保持平台原生。

## 里程碑

### M0：真机墨迹基线（已完成）

- Canvas、压感、颜色、笔宽、撤销、清空
- 自动保存和冷启动恢复
- 真机确认延迟、采样密度与压力范围

### M1–M2：编辑与圈选闭环（已完成）

- 工具模式：笔 / 橡皮 / 套索
- 多边形套索和笔画包围盒快速命中
- 选区浮动工具条：讲解、整理 Markdown、转正式文字
- 将选区离屏渲染成 PNG，并附结构化笔迹

### M3：BYOK 多模态 AI（基本闭环已完成）

- 设置页保存 endpoint、model、token
- OpenAI-compatible 适配器和一个国产模型适配器
- 请求预览、可拖动/最小化卡片、预设和自由多轮对话已完成
- 流式答案、取消、重试和 AI 结果可编辑卡片回写待继续

### M4.1：多笔记文件底座（已完成构建，待真机验收）

- 启动书架、新建/打开/重命名/删除、当前笔记保存
- 原子多笔记索引、旧 `padnote-current.json` 安全迁移
- 系统文件选择器无损导入/导出 `.padnote.json`

### M5：连续分页画布与公式可视化（已完成构建，待真机验收）

- 统一世界坐标、单指平移、双指缩放与跨设备相对缩放恢复
- 纵向页面堆叠、手动加页、末页底部阻力上拉自动加页
- schemaVersion 2 保存页面几何/页数/视口，兼容读取 schemaVersion 1
- AI 回复中的 LaTeX 由本地 KaTeX 编译为可视公式与 MathML

### M5.1：分页手感与可编译文本框（已完成代码与编译，待真机验收）

- 下一页纸张实时拉出、连续橡皮筋阻力、露出 1/3 松手确认、未达标平滑回弹
- 默认 LaTeX/可选 Markdown 的持久化 PPT 式文字对象：文字图标与画笔同组，选中“文字笔”后点页面位置插入；透明内容、点选边框、移动、右下缩放、双击编辑和输入实时编译
- schemaVersion 3 保存文本框源码/格式/世界坐标，继续读取 schemaVersion 1/2
- schemaVersion 4 保存跨页文本流的统一源码、字号、流 ID、片段顺序与逐页几何，继续读取 schemaVersion 1/2/3

### 0.10.0：文本流事实源与跨页移动（已完成代码与编译，待真机验收）

- `TextFlow` 成为唯一事实源，片段退化为派生物；`layoutFlow` 改为纯函数
- 锚点改为页相对坐标，修掉"跨页移动实际做不到"和"放下就自己跳走"的死区
- 拖任一片段整组移动 + 半透明幽灵预览；拖到视口边缘停留自动翻页
- schemaVersion 5 只保存 flows，片段在加载时重新派生，继续读取并迁移 1/2/3/4
- 片段视图按可见页 ±1 虚拟化，修掉多页笔记同时持有大量 WebView 的崩溃风险

### M5.2 及以后：可用的笔记产品

- 页面删除/重排、书架缩略图
- 图片/PDF/HiNote 兼容入口、Markdown/PDF 导出
- 增量存储、性能基准、发布签名与隐私说明

## M0 真机验收阈值

- 连续写 5 分钟无明显丢笔或错连。
- 轻压和重压肉眼可分，底部压力值会变化。
- 写满一屏后撤销和重绘无明显卡顿。
- 杀掉应用再启动，最后一次完整笔画能够恢复。
- 手掌误触暂未纳入 M0；确认设备 `sourceTool` 行为后在 M1 加“仅手写笔”策略。
