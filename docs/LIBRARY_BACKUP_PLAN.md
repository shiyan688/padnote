# 整库备份与恢复实现边界

对应问题10、18、22。以下为后续实现方案，当前应用尚未提供整库备份；不能据此建议用户卸载旧版。先完成当前会话功能，再分别实现和验证备份。

## 内容与格式

采用显式创建的本地归档，不依赖系统备份默认行为。备份预览列出笔记、关联PDF、自定义封面、知识库及占用空间，逐项报告不能读取的数据。已有图片包含在笔记JSON内，不二次漏存或重复提取。

归档使用独立格式版本、资源清单、每文件字节数和SHA-256。每项资源以内部生成的安全标识引用，不把用户提供的文件名直接作为恢复路径。笔记沿用现有schema及50MiB编码上限，PDF沿用100MiB和500页验证；总大小、条目数、图片解码预算另设限，按实际读写累计而不只相信ZIP头。

两端知识库存储不同：Android是带front matter的Markdown，iPad是JSON。归档采用共同条目描述，包含正文、标题、来源笔记标识、来源版本、生成时间；时间统一为Unix毫秒。导出/导入适配层负责转换，不直接复制某个平台的目录。封面也按笔记关联关系描述，不依赖两端目录相同。

模型密钥、Agent令牌、Keychain/Keystore材料、设备私钥、配对授权和含凭据的设置不进入归档。恢复后重新配置连接。导出操作明确说明归档含笔记正文；未经用户选择不发到云端。

聊天记录与电脑任务历史设置为明确可选范围，并在归档清单写明是否包含。跨设备恢复先作为可读历史，不能恢复审批权限、在途请求或自动续跑；旧材料不会自动发给重新配置的模型。远端产物没有下载到本机时不能写成已备份，只保存安全的离线说明。待会话、任务格式稳定后分别定义迁移，不能用复制运行时文件代替。

## 创建备份

先完成当前文档保存，选择一组固定修订并创建受控快照。资源复制和摘要放后台；复制期间若原件改变，重新获取该项或报告失败，不把不同修订混成一个成功项。仍有未保存修改时先提供保存/导出恢复路径，不能默默只备份旧版本。

归档写入临时文件，完成清单、摘要和可读性校验后才交付。支持进度和取消，取消不留下可误认完整的文件；失败保留原数据。逐文件流式处理，不把整库或整个ZIP解压到内存。

## 恢复

先读清单并在隔离暂存目录验证路径、重复条目、链接、压缩方法、实际解压量、内容摘要及文档/PDF关联。未知必需格式停止恢复，不能猜测后覆盖。校验完成前不修改当前资料库。

预览显示可恢复数量、损坏项、缺失资源、目标空间和同源冲突。默认导入副本；用户可逐项选择更新原笔记。更新前保留可恢复旧版，不以修改时间较新作为覆盖授权。选择副本时为笔记及所有关联资源统一重映射标识；旧会话不会获得新笔记的写权限。

使用持久恢复事务记录提交进度。每个笔记的JSON、PDF、封面和关联知识库组成完整恢复项，索引最后更新；中断后能继续或回退，不能显示半本成功。原备份文件保持不变。没有成功恢复的项保留可理解的错误，不静默跳过。

## 验证门槛

两端互导普通/PDF/图片笔记、自定义封面及知识库；比较数量、正文、页锚点、关联与摘要。覆盖重复导入、同源分别修改、同名不同ID、损坏条目、缺PDF、容量边界、路径穿越、ZIP炸弹、存储满、取消以及各提交点中断。

本机隔离目录和模拟器可先完成文件/事务验证。全新设备恢复、实际升级迁移及低内存压力仍需真机证据；在这些完成前保留问题22和正式分发的验收项。
