# 渲染失败后的恢复

对应TODO问题12、17，正在实施，尚未完成本批验证。先采用本地错误提示与手动修复，不增加模型调用。模型自动修复保留为后续选项，必须显示额外调用并设置预算。

## 用户看到什么

源码已写入、页面可显示和内容已核对分别记录。公式或图表渲染失败时，原笔记仍可打开和编辑；失败对象显示简短原因，并提供查看源码、复制、编辑及重新渲染。重新渲染不重新请求模型、不重复创建文字流，也不改变原笔迹。

会话中的普通文字回答应保留明确采用入口。恢复聊天后仍能选择写入；采用前重新检查来源、当前权限和文档状态。原材料过期时保留回答，不把旧位置自动套到新页面上。

PDF导出需要单独检查完整性。不能将丢失图表或公式的文件静默报告为完整成功。可提供“修复后导出”及明确标示的“按源码导出”，后者需要用户选择，并在导出预览中可辨认。

## 状态和执行约束

- 状态绑定文字流ID与实际渲染输入摘要，包含源码、格式、宽度、字号、行距和渲染器版本。改过源码后，旧错误或旧成功不能覆盖新状态。
- 每次渲染有独立代次；取消、编辑、删除、切笔记和Web内容进程退出使旧回调失效。失败后释放工作项，下一对象能够继续处理。
- 普通显示、预览及导出复用错误类别：本地资源缺失、语法错误、超时、内容过大、Web内容进程退出。UI不显示完整堆栈或未经处理的内部路径。
- Web页面装载、JavaScript执行和截图各有截止时间；并发请求不能共享同一个可被多次恢复的continuation。取消应使等待方及时返回，而不是只改变按钮文字。
- 本地重试只运行一次。失败对象不会因每次绘制而无限排队；用户改过源码或明确点击重试才再次尝试。
- 缓存失败状态与显示图片分别管理，不把临时缓存当作笔记原件。超限时先拒绝分配大图；布局测量不因失败将对象压成零高。
- 性能记录只含阶段、耗时、字节/像素数量与错误类别，不默认记录笔记正文、提示词、密钥或地址参数。

## 当前源码入口

Android的`CompiledTextWebView`在资源错误时只通知PDF监听器；普通显示仍需独立状态回调。`renderDocument`、结果气泡和纸面文字流都要覆盖，不能只修导出。保留已有离线资源与禁止网络加载策略。

Android渲染进程退出后，受影响的WebView不能继续使用，恢复入口必须重建它；单纯对原对象再次加载不算恢复。各视图分别清理，不能假设所有WebView均受影响。[Android WebViewClient API](https://developer.android.com/reference/android/webkit/WebViewClient#onRenderProcessGone(android.webkit.WebView,%20android.webkit.RenderProcessGoneDetail))

iPad的`CompiledTextRenderer.prepare`捕获失败后未报告对象状态；`readyWeb`等待装载没有独立截止时间，Web内容进程退出也没有完成等待者。`MathTextView`的JavaScript调用需要报告失败。需先收束共享worker的取消、错误和队列生命周期，再连接编辑器与导出UI。

iPad的WK快照宽度以点为单位。分配前的预算必须结合显示比例估算像素，生成后再检查实际位图；不能直接把点面积当作内存预算。[Apple snapshotWidth说明](https://developer.apple.com/documentation/webkit/wksnapshotconfiguration/snapshotwidth?changes=l_7&language=objc)

## 验收

使用真实本地WebView/WKWebView渲染合法中文、长公式、错误Mermaid、缺失资源、超限尺寸和可控超时；检查源码始终可编辑、错误对象可定位、重试不增加对象、修改后旧回调不能覆盖新结果。随后连续渲染正常对象，证明一个失败不会阻塞整个队列。

至少有一项实际界面验证错误提示与按钮可达；导出文件另做内容和视觉检查。注入错误证明异常处理路径，不能据此宣称设备低内存或真实Web内容进程崩溃已验收。
