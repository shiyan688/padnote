## 可重复场景

使用临时笔记和测试模型档案，不使用私人笔记或真实令牌。网络夹具返回普通文字、合法工具调用、错误和可控的晚到结果；每一项都检查实际应用控制路径。真实服务验收另行记录供应商、版本、系统、网络和结果。

| 操作 | 用户应看到的结果 | 需要核对的证据 |
| --- | --- | --- |
| 在笔记A聊天、收起，取消圈选后再点AI | 恢复A的记录、材料和执行者，可以继续 | 由工具栏打开；下一请求保留合法历史，不只是恢复展示 |
| 切到笔记B，再回到A | 两本笔记的记录和来源各自独立 | 实际请求中没有另一笔记的标记 |
| 重建Activity或重开存储后恢复A | 记录与有效发送上下文能继续 | 明确记录是视图/Activity重建、文件重开还是进程重启 |
| 新圈选后打开已有会话 | 明确选择继续旧材料或更新为新圈选 | 预览和请求使用同一份材料；选择前不得静默替换 |
| 切模型、端点、凭据或写权限 | 旧聊天可看；下一轮建立新上下文 | 检查实际请求字节，不含旧转写、图片和工具结果 |
| 两阶段回答 | 每轮能看见转写模型与回答模型 | 展示记录冻结在该轮执行时，之后改配置不改旧标签 |
| 合法工具调用后再收起重开 | 结果卡显示实际应用状态，可安全定位/撤销/重应用 | 依据当前文档与持久修改凭据；不得依赖旧布尔值 |
| 同一会话连续两次写入 | 第二次能基于第一次已成功提交的内容继续 | 真正经过生产commit，下一轮来源基线已推进 |
| 回答期间手写、改文或撤销，再完成旧回答 | 旧结果不覆盖新内容 | 外部编辑使来源失效；保留可查看的回答和原因 |
| 清空后让旧请求完成，再重开 | 仍是已清空状态 | UI回调、后台保存、文件恢复三条路径均不复活记录 |
| 清空后在同一面板重新发送 | 可以开始新对话；未选择材料时提示重新选材 | 不必靠关闭面板或重启应用解除失效状态 |
| 清空时残留旧tmp/bak，或旧Store持有更高修订 | 不恢复已经清空的会话 | 持久清空标记与文件候选共同校验；异常不能当首次使用 |
| 写入失败、文件损坏或超限 | 提示未保存，原有效版本仍可恢复；提供导出 | 比较文件字节；不静默截断聊天，不覆盖唯一损坏原件 |
| 撤销AI新增内容，删除原空页，再添加新页并冷重开 | 旧结果不能重新应用到替换后的页面 | 页数和可见内容相同也校验持久页面结构修订 |
| 替换或移除关联PDF | 停止沿用旧上下文并提示来源变化 | 即使PDF页数相同，也校验实际文件摘要 |
| 删除笔记 | 关联会话不再恢复 | 迟到保存不能重新创建被删笔记的会话 |

## 可用性检查

在平板尺寸和大字号下检查历史、来源提示、发送/取消、收起、清空、错误恢复入口可达；键盘出现后仍能发送和收起。长历史可滚动，状态及结果操作不能被配置控件挤出窗口。图片解码和磁盘工作不进入逐点书写路径，不为判断工具支持自动发请求。

真实Android平板与iPad暂不可连接；触笔、TalkBack/VoiceOver、锁屏、系统回收、低内存与弱网在设备可用后单独补验。没有这些结果时，报告只写本机、模拟器或注入网络覆盖，不称真机或真实Agent验收通过。
