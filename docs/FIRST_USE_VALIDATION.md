# 首次使用流程改善：源码验证记录

本轮只修改源码和文档，没有构建、签名或发布新 APK。公开下载仍为 v0.18.0-beta.13；[该版本测试记录](BETA13_TESTING.md)不代表本轮改动已经通过同样的测试。

## 改动

- 书架引导集中到写或导入、圈选与模型配置、讲解并保留笔记，提供新建与导入按钮；已关闭引导的用户不被重新打扰。
- 没有模型档案时，打开 AI 设置直接进入第一个配置表单，省去空列表和新建按钮。由提问触发时，保存后沿原有路径继续，仍需发送确认。
- 第一次配置说明需要什么信息、服务商费用、保存不发请求，以及电脑 Agent 并非前提；表单可滚动，便于查看底部字段。
- 七种界面语言同步引导文案。翻译尚未经过母语者审核。
- 中英文首页、llms.txt、快速指南和 FAQ 统一安装入口、模型成本和验证范围；修正旧 AI 文档中关于取消、默认知识库权限和页面地图正文的过时描述。

## 本机检查

- `git diff --check`：通过。
- Android `res` 下 78 个 XML 文件解析通过；七个语言目录都提供新增提示，未发现重复资源名称。
- 本轮文档本地 Markdown 链接目标检查通过。
- `node tools/static-check.mjs`：未通过。现有脚本将 file URL 的 pathname 当 Windows 路径，得到 `E:\E:\...`。临时诊断绕过该路径及 POSIX 文件模式检查后，还遇到现有“向上翻页 · 1:1 跟手”硬编码文字断言与已本地化源码不匹配。诊断修改已撤回，没有调整这些检查来宣称通过。
- 尝试使用本机 JetBrains JBR 21 运行 `:app:testDebugUnitTest --offline`：Gradle wrapper 无法在用户目录创建分发锁，未启动测试。工作区没有 SDK 配置，常用 SDK 位置也未找到；没有安装工具链、下载 SDK 或扩大环境改动。

没有执行 Java 编译、JVM 测试、模拟器 UI、实体平板、真实模型或 Agent 请求。XML 与静态阅读不能证明界面尺寸、键盘可达性或运行时行为。

## 发布前还需检查

1. 用干净应用数据打开书架，新建和导入按钮分别进入已有流程；关闭引导后重开不再显示。
2. 写几行或导入 PDF → 圈选 → AI → 设置，在无档案时直接出现表单；已有档案时仍出现管理列表。
3. 没有输入任何信息时取消：选区和问题仍可继续，且没有网络请求。
4. 从“讲解”进入首次配置，保存后显示原有材料与接收地址确认；取消确认不发请求。保存配置本身不产生模型调用。
5. 在平板竖屏、大字号和软键盘打开时，检查表单可以滚动到模型与密钥字段，保存/取消按钮可达。
6. 用已授权的测试服务分别验证“仅卡片”和“允许写入”，核对实际输出、保存/重开和错误提示；真实费用与模型质量单独记录。
