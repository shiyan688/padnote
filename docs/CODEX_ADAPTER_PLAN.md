`codex_transport.py`管理独立子进程、初始化、响应关联、通知、需要调用方明确回答的反向请求及关闭。请求和队列有边界，未开始发送的取消请求不会补发，已开始发送的取消只停止本地等待，不能据此认定上游操作被取消。默认单帧4MiB，出站排队和入站事件各16MiB编码字节预算；这不是Python进程实际内存上限。审批数据只由传输层转交，没有自动批准行为。

## 官方接口

Codex提供App Server，支持会话、轮次、流式事件及审批；默认通过stdio交换JSONL。公开WebSocket传输仍标为实验性。可由目标CLI版本生成对应schema。登录流程也由App Server提供。[官方App Server文档](https://learn.chatgpt.com/docs/app-server)

2026-09-24已使用本机 `codex-cli 0.153.4` 离线导出默认schema，没有启用experimental字段、启动App Server或发起模型任务。输出和哈希清单保存在 `dist/todo-review/codex-0.153.4-schema/` 与 `codex-0.153.4-schema-manifest.json`。这只证明本机CLI的接口定义，不代表用户另一台电脑装有相同版本。

该定义包含 `thread/start`、`thread/resume`、`turn/start`、`turn/interrupt` 与命令/文件/权限审批。中断要求同时提供threadId和turnId；反向审批也携带两者，适配时必须与本设备任务匹配。`turn/start`虽有可选clientUserMessageId，schema未说明其去重保证，不能把这个字段自行当作持久幂等键。历史应优先使用分页接口，避免把整个会话一次载入并传给平板。

## PadNote采用方式

建议电脑助手持有一个受控的stdio子进程，平板沿用现有设备配对和任务接口。登录留在电脑上；平板不需要复制Codex登录文件或模型密钥。此选择复用当前助手架构，不增加PadNote公网服务。

每个Codex实例有独立ID，用户明确选择可使用的项目目录。每个PadNote任务保存电脑实例、设备授权、会话/轮次ID、源材料版本及最后确认状态。只查询这些任务对应的会话，不默认把电脑上的所有Codex历史公开给平板。

Adapter需同时处理普通响应、通知及反向请求。审批映射保留原请求ID与具体动作；平板只回答仍待处理、属于本设备任务的请求。批准一次不能扩大成永久规则或整个项目授权。网络请求权限、命令执行和文件改动分别呈现。

断线时保留任务身份，重连先读权威状态，再决定恢复订阅或继续同一会话。不能因为提交超时就创建另一轮；未确认是否提交成功时显示待确认。取消也要等待远端确认，不能把停止本地轮询当作任务结束。

文件仅从本任务允许的目录发布，记录大小、摘要与原材料关联。Codex现有沙箱和审批配置继续生效；助手传输权限不等于允许执行任意电脑命令。

## 验收顺序

1. 固定并记录CLI版本，生成schema；本地假进程验证初始化、乱序响应、事件、错误、进程退出及JSONL大小限制。
2. 验证多实例、多设备、撤销、旧审批、重复事件、未知提交和重启恢复；平板输入不能自由指定另一个任务的会话ID或项目路径。
3. 用户电脑完成登录后，先运行只返回文字的小任务；再验证图片材料、审批、明确停止及产物取回。
4. 在Windows/WSL2和目标平板实测网络、休眠、路径映射与前后台行为。通过前保持“未接入/实验中”标识，不把协议研究当成产品能力。

模型、权限档案及可用登录方式以实际CLI和账号响应为准。首批适配不默认开启实验字段，也不修改用户现有Codex配置。
