# Android AI 请求：取消、重试和转写校对

本页描述本地开发版本；公开 beta.6 尚无这套请求控制。测试与分发状态见 `TODO_EXECUTION.md`。

发送后，原来的“发送”按钮变为“取消”。取消会使当前回调失效，并中断、断开本地 HTTP 请求；已经执行的笔记操作保留。服务商可能已经收到材料并产生费用，取消不表示服务商撤销了处理。

尚未执行笔记工具的请求可以显式重试。重试沿用同一条用户消息、圈选图片、已授权材料和接收配置，不追加重复提问。更换材料、接收配置或笔记上下文后，旧请求不再作为可用重试。没有为未知的兼容模型供应商承诺请求幂等；超时重试仍可能再次计费。

笔记工具已经开始后，不提供整轮重放，避免重复添加文字或修改布局。工具结果与后续收尾回复分开处理。若等待期间原文发生变化，旧请求不能再按原布局写入；回答保留在卡片中，用户重新选取材料后再发起操作。

两段式模式默认识别完成后直接调用回答模型。需要时可启用“先校对转写”：应用展示可编辑文本，确认后直接发送修订文本给回答模型，不再次识别图片。取消校对后重试，应重新展示已有转写供核对，不能遗漏转写或绕过校对。已经接受的转写可以用于追问。

读取范围和写入权限独立。一次请求开始后冻结两者；“仅卡片”不能因请求中途切换按钮而变成落笔授权。来源与接收者改变时清理历史的规则仍按 `AI_READ_SCOPE.md` 执行。

当前证据：4项阻塞假连接测试覆盖取消与线程复用；6项状态测试覆盖单条用户消息、校对/回答重试路由、工具开始后禁止重放和原文修订守卫；1项原生测试打开真实生产校对弹窗，编辑文本并验证只接受一次。它们不是完整OCR/回答供应商链路的端到端验收。真实供应商行为和真机网络切换另行测试，不用假连接推断远端已停止或没有计费。
