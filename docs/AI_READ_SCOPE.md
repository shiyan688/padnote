# AI 材料读取边界

本规范落实 TODO 11，并约束问题 7/9 的会话与来源恢复。读取权限与纸面写入权限是两个独立对象。

## 默认请求

默认只发送用户已经看到的选区图片、当前问题/本会话历史，以及不含正文的布局地图。地图保留页/条带、占位、空白容量、对象 ID、格式和尺寸，不能包含文字流 source、摘录、图片数据或圈选外 OCR。

`read_page_map` 后续工具调用遵循同一边界；模型改变 page 参数不能获取额外正文。PageMap 在生成时就避免加入 source，不能仅修改提示词或在第一轮临时删除字段。布局与写入位置仍须正确，不能为避免读取而禁止基本排版能力。

## 额外材料

知识库默认未授权。用户明确选择具体笔记后，客户端以稳定 ID 和内容修订/摘要冻结本次可读快照；搜索只索引这份快照，读取只能返回快照内的笔记。一个“可写入”开关不授予知识库权限。

界面显示选中材料的名称、数量与内容预览入口。未经选择的标题、命中统计、摘录和正文均不能出现在工具结果中。猜中路径/标题/ID也不能绕过校验。无授权时不向模型提供知识库工具，同时调用执行层仍须拒绝越界，不能仅隐藏按钮。

额外页面如被支持，必须经页面选择与内容预览单独授权；跨页文字流不能因锚点落在授权页就把整条 source 带出。实现前继续使用圈选图片和用户选定知识库，不虚构页级正文授权。

## 历史与接收方

会话上下文与以下对象绑定：笔记与材料快照、读取授权、接收服务及模型档案身份。缩小/扩大材料范围或更换接收服务时，旧模型消息与工具结果不能自动加入新请求。开始新的上下文并重新展示发送确认；旧对话如保留，只作为历史可见，不能默默再上传。

修改配置与换档案同时重置模型的工具能力缓存；取消或使旧回调失效，不能让旧服务的晚到结果写入新会话。网络请求开始后，授权快照保持不可变；UI 禁止途中改变本轮范围，之后的变更只作用于新的请求。

两阶段模式的识别图片仍来自同一选区；回答阶段只收到该选区的转写及本次明确授权材料。收紧读取范围后，不得从旧转写或 tool 历史重新夹带被排除内容。

## iPad 来源

打开 AI 时一次性冻结 image + note ID/revision/document + page + bounds。滚动、翻页、重选不能使旧图对应新位置。会话明确显示来源；更换材料通过独立动作重建上下文。写入时仍校验当前文档与原快照相容，不兼容的结果保留待应用而不覆盖用户编辑。

## 验证

在圈选内、同页圈选外、相邻页、另一知识库笔记分别放唯一标记。检查实际请求序列化字节与 tool 返回值：

1. 默认首次请求、第二轮 read_page_map 指定其他页、追问、两阶段回答不包含任何未授权正文标记。
2. 仅授权 A 后，搜索/按标题/按 ID 读取不能返回 B 的标题、数量提示或正文；底层 B 文件不被读取。
3. A 内容更新不能静默替换已预览的快照；新选择重新确认材料。
4. 收紧范围或更换服务后，旧 tool 消息不再出现在下一次实际 HTTP 请求。
5. 同样的读取范围下，允许新增文字仍可正确定位和分页；只读权限不能新增/移动。
6. iPad 打开旧选区后翻页或编辑，材料位置保持原值，回写校验阻止覆盖新文档。

实际请求测试应使用应用真实序列化器或 URLProtocol/本机假服务，不能仅检验一个未被生产代码调用的过滤函数。原生截图遮罩与交互绑定需要模拟器/真机另验。
