# 渲染恢复验收

对应TODO12/17。本批正在实现，以下是验收要求，不表示已经通过。当前完整本地检查点仍为Android r12 / iPad conversation r4。

| 场景 | 应有行为 | 本地证据要求 |
| --- | --- | --- |
| 合法中文、长公式、图表 | 正常显示并保持既有分页、字号、宽度 | 真实WebView/WKWebView，保留纸面与PDF回归 |
| KaTeX或Mermaid语法错误 | 显示具体类别；源码仍完整；导出不能静默当完整成功 | 错误必须来自实际渲染，不只测试预先设好的状态 |
| 本地资源缺失 | 可理解的错误和恢复入口，不挂住队列 | 受控缺失资源夹具；随后正常对象成功 |
| 加载、脚本或截图超时 | 各阶段有界退出，释放工作项，失败不无限自动重试 | 可控超时与下一任务验证；不能只检查按钮文案 |
| 改源码后旧结果晚到 | 旧成功/错误不覆盖新输入，不误改几何或状态 | 两个代次交错回调；新源码、宽度和字号仍正确 |
| 删除、换笔记、取消 | 旧回调失效，共享相同显示输入的其他使用方仍可完成 | 文档身份与使用方分别断言 |
| 超大源码或像素 | 分配前拒绝，保留可读原文和编辑入口 | 实际边界与累计像素；不能只依赖缓存总额 |
| 失败后的查看/复制/编辑/重试 | 按钮可达，一次点击只重试本地渲染，不新增对象或调用模型 | 至少一项实际界面操作，比较对象数量/源码/修订 |
| 冷恢复普通文字回答采用 | 原来源仍有效时可写入；过期则解释原因；重复采用被拒绝 | Android重开会话、修改源、写入后尚未保存会话等边界 |
| PDF遇到失败对象 | 完整导出明确失败；若支持源码版必须由用户选择并可辨认 | 回读实际PDF内容，目视检查警示与源码不遗漏 |

聊天中编辑本地显示副本不能悄悄改写原模型回复或发送上下文。纸面源码编辑走已有文档保存与撤销流程。错误状态属于显示派生数据，不可用错误提示替换持久源码。

失败注入、Activity重建、显式force-stop和真实系统低内存回收分别记录。没有设备时可以完成前几类本地验证，但不声称通过触笔、锁屏、系统回收或最低设备内存验收。每轮使用独立源快照、日志与产物；失败记录保留。
