# 整本数字化：暂停、恢复与费用边界

本文件说明正在本地验证的实现；公开 beta.6 不包含这套恢复流程。构建与运行证据以 `docs/TODO_EXECUTION.md` 为准。

## 使用方式

在笔记中打开“整理到知识库”。先核对整本上传范围和目标模型，再开始。每页转写成功后，应用将结果保存到本机；全部页面完成后才更新知识库。

若失败、取消或退出应用，重新打开同一本笔记的整理入口，可以查看已保存的批次和部分结果。原文与模型配置没有变化时，继续操作只发送缺少的页。若页面已全部完成、只是知识库保存失败，重试只写本地文件，不再请求模型。

同一批次同时只允许一项整理操作。取消后，如果旧请求尚未结束，新窗口也不能抢先重发。应用会在请求前记录正在处理的页；如果没有保存到返回结果，下次继续会提示该页可能已经处理并计费，需要确认后才会重试。

原文内容、PDF、页数或接收模型配置变化后，不会把新结果拼到旧批次。旧稿保留供预览、导出；新批次重新处理当前原文。转写本身没有自动正确性保证，应回看原页，尤其是数字、负号和公式。

## 保存什么

检查点保存页码、已完成文字、原文内容摘要、模型配置身份和批次状态；不保存模型 API Key。源指纹不把滚动、缩放或单纯保存时间当作内容修改。任务恢复不是跨设备同步，也不会自动将检查点上传到电脑 Agent。

Android 运行时冻结纸面快照，把已有文字直接并入结果；OCR 图像包含手写、图片及原 PDF。iPad 从冻结的文档及受校验的 PDF 副本生成页面。PNG 按页生成，不为整本任务预存全部页面图片。

未完成稿单独存放并明确标记，不参与知识库检索，不覆盖已完成笔记。无法解码的检查点会显示为损坏项，不能当成可继续任务。文件损坏不等于原始笔记被删除。

## 取消的含义

“取消”或“暂停”停止本地等待及后续页面请求，阻止晚到响应继续写入。已发送的请求可能仍由供应商完成并计费。无法判断服务器是否处理过的当前页，需要用户再次确认继续后才会重试；不承诺供应商能按请求去重。

应用退到后台后保留已经落盘的页面。恢复依靠重新打开入口读取检查点，不依赖应用一直在后台运行。强杀、磁盘写满或设备突然断电仍有各自的验证边界；网络返回但尚未保存的一页可能需要重做。

## 验收场景

- 第二页失败，关闭并重新打开：第一页保留，只请求剩余页。
- 取消后模拟服务器迟到返回：不增加已保存页数，不覆盖原知识库。
- 页面全部完成而知识库写入失败：重试保存时模型请求数不增加。
- 修改正文、PDF、模型配置：旧稿能查看，新任务不能混入旧页。
- 仅滚动、缩放或保存时间变化：仍能找到同源进度。
- 损坏检查点、并发旧修订、保存中断：明确拒绝或恢复有效文件，不能静默覆盖较新进度。
- 两个窗口同时恢复同一批次：只有持有执行权的一方能发请求；另一方不能修改进度。旧请求实际结束后才释放执行权。
- 请求已发送但返回结果保存失败：重开时显示未确认页，不自动重发；显式确认重试可能再次计费。
- 真机锁屏、系统回收及存储空间耗尽：另行测试，不用单元测试代替实机结果。
